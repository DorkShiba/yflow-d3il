# Stacking 재엽 담당 ID OOD 결과 통합

재엽 담당 context 16–22에서 ID와 OOD A 세 강도의 32조합 평가를 완료했습니다. 총 896개 평가 단위, 2,688 rollout이며 방법 실행 실패는 0회입니다. **ID에서는 ①②③⑤의 성공률이 19.05%에서 57.14%로 높아졌지만, OOD A_mid와 A_strong에서 이 조합과 다섯 방법 전체 조합은 성공하지 못했습니다.**

## 평가 범위

- 각 조건은 같은 7개 context와 noise seed 0·1·2를 사용합니다. 조합·조건당 21회입니다. 선택된 base context는 test_059, test_062, test_069, test_070, test_072, test_075, test_077입니다.
- 35만 step EMA 모델과 train-only normalizer, 공개 관절 PF 캐시를 고정했습니다. 한 번에 16 step을 계획하고 8 step을 실행하며, Euler 적분 10회, 제어 간격 0.03초, 최대 1,000 step, 모사 추론 지연 0입니다. 재학습·체크포인트 재선택은 없습니다.
- A_weak는 1cm, A_mid는 5cm, A_strong은 이동 가능한 블록만 18cm 이동한 배치입니다. 강도는 서로 섞어 평균하지 않습니다.
- ID는 RTX 3090, OOD는 RTX 3090·RTX A5000·RTX A6000에서 실행했습니다. 같은 조건·context의 조합들은 같은 장비를 사용했지만 **ID와 OOD 사이에는 장비 차이가 있습니다.** 강도에 따른 순수 효과나 계산 시간 차이를 장비 효과와 분리한 결과는 아닙니다.
- 담당 7개 context의 결과이며 팀 전체 30개 context 결과나 통계적으로 확정된 순위로 해석하지 않습니다. 단일 학습 seed의 시뮬레이션입니다.

## 결과 해석

- id: S29의 실제 손 jerk는 baseline 대비 -22.52%, S31은 -23.68%입니다. S31의 청크 경계 속도 변화는 -54.70%입니다.
- A_weak: S29의 실제 손 jerk는 baseline 대비 -5.73%, S31은 -2.42%입니다. S31의 청크 경계 속도 변화는 -48.42%입니다.
- A_mid: S29의 실제 손 jerk는 baseline 대비 -0.93%, S31은 +4.14%입니다. S31의 청크 경계 속도 변화는 -49.99%입니다.
- A_strong: S29의 실제 손 jerk는 baseline 대비 +2.91%, S31은 +0.71%입니다. S31의 청크 경계 속도 변화는 -52.06%입니다.
- ID에서는 S29가 S31보다 성공 1회 많고, S31은 실제 손 jerk와 경계 변화가 더 작습니다. A_weak에서는 S31이 baseline보다 성공 2회 많지만 S29의 실제 손 jerk가 더 작습니다. 성공률과 부드러움이 같은 조합에서 항상 함께 개선되지는 않았습니다.
- A_mid·A_strong에서 S29·S31의 경계 변화가 줄어도 성공률 개선으로 이어지지 않았습니다. S31의 실제 손 jerk도 두 강도에서 baseline보다 증가했습니다. 명령 변화의 완화와 실제 손 궤적의 개선을 구분해야 합니다.
- JSON에는 32조합 전체 수치와 조건 안에서 S29·S31을 baseline과 비교한 context-paired bootstrap 95% 구간(10,000회, seed20261116)을 보존했습니다. 장비가 다른 ID 대 OOD 차이의 신뢰구간으로 사용하지 않습니다.

## 검증과 재사용

원본 결과 896개와 궤적 NPZ 896개의 누락·중복·ZIP CRC를 검사했고, 보고서의 context별 지표 896행을 원본 episode에서 재계산한 값과 대조했습니다. ID 보고서는 기존 메인 파일과 바이트 단위로 같습니다. source commit, code fingerprint, PF 캐시, context 목록, noise seed 및 OOD 파일 해시를 확인했습니다. 원본 결과와 실행 로그는 별도 로컬 백업에 보존했습니다.

실행 커밋은 `4c09aab2480f5e6ce7b705f8e8d32443c2bee1c3`, code fingerprint는 `ae2ad005e1a3311c058a25f68ed4dff83287b7f5b987a9195aa8214e4bd18cfa`입니다. 모델·정규화·PF 캐시·context·조건별 원본 보고서 및 백업 해시는 통합 JSON에 기록했습니다.

조건별 원본 보고서는 기존 팀 merge 형식을 유지합니다. 이 통합 요약은 조건을 합쳐 한 성능값으로 만들지 않으며, 팀 전체 통합의 입력 보고서를 대체하지 않습니다.
