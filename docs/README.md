# 1. Dataset: d3il

아래 설명은 `data/`에 저장된 상태 기반 전처리 데이터(`sincos_v1`)를 기준으로 한다. 이미지 대신 로봇 손과 블록의 위치·방향을 사용하며, 입력 항목과 분할의 기준은 각 데이터셋의 `manifest.json`이다.

## 1.1. Pushing

- 문제 상황: 로봇 손으로 빨간 블록과 초록 블록을 각각 목표 구역으로 미는 작업이다. 로봇 손과 두 블록의 현재 상태를 바탕으로 다음 시점의 목표 손 위치 변화량을 예측한다.
- 데이터 특징:
  - 저장 위치: [`data/pushing_sincos_v1/`](../data/pushing_sincos_v1/). 시연 하나를 NPZ 파일 하나로 저장하며, `train/`, `val/`, `manifest.json`으로 구성된다.
  - 데이터 규모: 총 2,000개 시연, 463,386개 상태·행동 쌍이다. 시연 길이 `T`는 최소 152, 중앙값 230, 최대 356시점이며, 기록 간격은 0.035초다.
  - 분할: 공식 `train_files.pkl` / `eval_files.pkl`을 따른다. 학습은 1,800개 시연·417,518쌍, 검증은 200개 시연·45,868쌍이다.
  - 상태: **12차원**으로, 아래 순서로 저장된다. 인덱스 범위는 Python 슬라이스처럼 끝 인덱스를 포함하지 않는다.

    | 인덱스 | 값 | 의미 |
    |---|---|---|
    | `0:2` | `robot.des_c_pos.x, y` | 제어기가 추종하도록 지정한 목표 손 XY 위치 |
    | `2:4` | `robot.c_pos.x, y` | 실제 로봇 손 XY 위치 |
    | `4:8` | `red-box.x, y, sin_yaw, cos_yaw` | 빨간 블록의 XY 위치와 z축 회전 방향 |
    | `8:12` | `green-box.x, y, sin_yaw, cos_yaw` | 초록 블록의 XY 위치와 z축 회전 방향 |

  - 행동: **2차원** `[Δ목표 손 x, Δ목표 손 y]`이며, `actions[t] = des_c_pos[t+1, :2] - des_c_pos[t, :2]`로 계산한다. 실제 손의 변위나 절대 위치가 아니며, 시간 간격으로 나눈 속도도 아니다.
  - 방향 표현: 원본 블록 쿼터니언에서 yaw를 계산한 뒤 `sin(yaw)`, `cos(yaw)` 두 값으로 저장한다. 각 값의 범위는 `[-1, 1]`이며, 공식 로더의 `tan(yaw)` 표현을 변경한 전처리본이다. 목표 구역 위치는 상태 입력에 포함하지 않는다.
  - 파일 내 배열: 원본 시연이 `T`시점일 때 다음 상태와 짝지을 수 있는 `T-1`개의 전이를 저장한다.

    | 키 | shape | dtype / 의미 |
    |---|---|---|
    | `obs` | `(T-1, 12)` | `float32`, 현재 상태 |
    | `actions` | `(T-1, 2)` | `float32`, 목표 손 XY 변화량 |
    | `next_obs` | `(T-1, 12)` | `float32`, 다음 상태 |
    | `timestamps` | `(T-1,)` | `float64`, 현재 시점의 원본 시각(초) |
    | `next_timestamps` | `(T-1,)` | `float64`, 다음 시점의 원본 시각(초) |

  - 전처리 상태: 정규화, 패딩, 시퀀스 길이 고정, 행동 클리핑, 제약 라벨 생성은 적용하지 않았다. 학습 시 시연 경계를 넘어 시퀀스를 연결하지 않아야 한다.

## 1.2. Inserting

- 문제 상황: 장벽이 있는 공간에서 로봇 손으로 세 블록을 목표 구역으로 밀어 배치하는 작업이다. 로봇 손과 세 블록의 상태를 바탕으로 다음 시점의 목표 손 위치 변화량을 예측한다.
- 데이터 특징:
  - 저장 위치: [`data/inserting_sincos_v1/`](../data/inserting_sincos_v1/). 시연 하나를 NPZ 파일 하나로 저장하며, `train/`, `val/`, `manifest.json`으로 구성된다.
  - 데이터 규모: 총 800개 시연, 792,387개 상태·행동 쌍이다. 시연 길이 `T`는 최소 533, 중앙값 952, 최대 2,355시점이며, 기록 간격은 0.035초다.
  - 분할: 공식 분할 대신 초기 조건인 context를 이용한 자체 그룹 분할을 사용한다. context를 소수 6자리로 반올림해 같은 그룹으로 묶고, seed 42로 전체 793개 그룹 중 80개를 검증에 배정했다. 학습은 718개 시연·711,908쌍, 검증은 82개 시연·80,479쌍이며 분할 간 context 그룹 중복은 없다. 모든 근접 초기 조건이 분리됐다는 의미는 아니다.
  - 상태: **16차원**으로, 아래 순서로 저장된다. 이 입력 구성은 팀에서 정의한 전처리 규격이다.

    | 인덱스 | 값 | 의미 |
    |---|---|---|
    | `0:2` | `robot.des_c_pos.x, y` | 제어기가 추종하도록 지정한 목표 손 XY 위치 |
    | `2:4` | `robot.c_pos.x, y` | 실제 로봇 손 XY 위치 |
    | `4:8` | `box-1.x, y, sin_yaw, cos_yaw` | 첫 번째 블록의 XY 위치와 z축 회전 방향 |
    | `8:12` | `box-2.x, y, sin_yaw, cos_yaw` | 두 번째 블록의 XY 위치와 z축 회전 방향 |
    | `12:16` | `box-3.x, y, sin_yaw, cos_yaw` | 세 번째 블록의 XY 위치와 z축 회전 방향 |

  - 행동: **2차원** `[Δ목표 손 x, Δ목표 손 y]`이며, Pushing과 동일하게 `actions[t] = des_c_pos[t+1, :2] - des_c_pos[t, :2]`로 계산한다. 실제 손의 변위, 절대 위치, 속도와 구분한다.
  - 방향 및 고정 조건: 블록 방향은 원본 쿼터니언에서 계산한 `sin(yaw)`, `cos(yaw)`로 표현한다. 목표 손 높이는 `0.12235930599088184`, 목표 손 방향은 `[0, 1, 0, 0]`(`w, x, y, z` 순서)으로 고정되어 있다. 목표 구역 위치는 `[0.3575, 0.276, 0]`, `[0.525, 0.4535, 0]`, `[0.6925, 0.276, 0]`이며, 목표 구역과 장벽 배치는 상태 입력에 포함하지 않는다.
  - 파일 내 배열: 원본 시연이 `T`시점일 때 다음과 같이 저장된다.

    | 키 | shape | dtype / 의미 |
    |---|---|---|
    | `obs` | `(T-1, 16)` | `float32`, 현재 상태 |
    | `actions` | `(T-1, 2)` | `float32`, 목표 손 XY 변화량 |
    | `next_obs` | `(T-1, 16)` | `float32`, 다음 상태 |
    | `timestamps` | `(T-1,)` | `float64`, 현재 시점의 원본 시각(초) |
    | `next_timestamps` | `(T-1,)` | `float64`, 다음 시점의 원본 시각(초) |

  - 전처리 상태: 정규화, 패딩, 시퀀스 길이 고정, 행동 클리핑, 제약 라벨 생성은 적용하지 않았다. NPZ에는 context 전체가 포함되지 않으므로 초기 조건 재현에는 원본 데이터 또는 별도 평가 context가 필요하다.

# 2. FM Baseline

물리 제약 보정이 없는 조건부 Flow Matching(CFM) 모델이다. [`fm_baseline/train.py`](../fm_baseline/train.py)는 외부 HardFlow의 `TemporalUnet`과 `FlowMatcher`를 사용한다. 아래 설정과 수치는 명령행 기본값이 아니라 `fm_baseline/results/`에 저장된 두 베이스라인의 설정·학습 로그·평가 결과를 기준으로 한다.

## 2.1. Pushing

- 모델의 입력과 출력 의미와 차원:
  - 한 시점의 학습 데이터는 `[행동 2차원, 상태 12차원]` 순서의 14차원 벡터다. 상태 항목의 순서는 1.1절과 같다.
  - 학습 배치는 `(B, 16, 14)`이며, 저장된 베이스라인의 배치 크기 `B`는 32다. 조건은 각 구간의 첫 상태 `s₀`로, shape은 `(B, 12)`다. 과거 관측 여러 개를 조건으로 넣지는 않는다.
  - 신경망은 노이즈가 섞인 시퀀스 `(B, 16, 14)`와 생성 시간 `τ` `(B,)`를 받아 같은 shape의 변화 방향(벡터장)을 출력한다. `τ`는 노이즈에서 데이터로 이동하는 생성 과정의 시간이며, 로봇의 실제 기록 시간과 구분한다.
  - 이 벡터장을 적분한 최종 결과가 상태·행동 시퀀스 `(B, 16, 14)`다. 실제 제어에는 각 시점의 앞 2차원인 목표 손 XY 변화량을 사용한다. 생성된 상태를 다음 실제 관측 대신 사용하지 않는다.

- 데이터 전처리 방법:
  - **NPZ 생성 단계:** [`prepare_pushing.py`](../preprocess/prepare_pushing.py)가 원본 시연에서 목표 손 XY, 실제 손 XY, 두 블록의 XY와 `sin(yaw), cos(yaw)`를 추출한다. 목표 손 XY의 차분을 행동으로 계산하고, 공식 학습·검증 분할에 따라 시연별 NPZ를 저장한다. 이 단계에서는 시연 길이를 유지하고 정규화하지 않는다.
  - 저장 후 배열·유한값·0.035초 간격, `현재 목표 XY + 행동 ≈ 다음 목표 XY`, `sin²(yaw) + cos²(yaw) ≈ 1`을 검사한다.
  - **학습 로딩 단계:** `load_split()`이 NPZ의 `obs`, `actions`만 읽고 `[actions, obs]`로 결합한다. `next_obs`와 timestamp는 현재 학습 손실에 직접 사용하지 않는다. 차원·길이 일치와 NaN/Inf를 검사한다.
  - **정규화:** 학습 분할 전체에서 채널별 최솟값 `lo`, 최댓값 `hi`를 계산한다. `center=(hi+lo)/2`, `scale=(hi-lo)/2`, `x_norm=(x-center)/scale`로 변환한다. `scale < 1e-8`인 채널은 scale을 1로 둔다. 검증·추론에도 저장된 동일 통계를 쓰며, 검증 값이 학습 범위를 벗어나면 `[-1, 1]` 밖으로 변환될 수 있다. 값의 클리핑은 하지 않는다.
  - **길이 16 구간 추출:** 시연에 `N=T-1`개 행이 있으면 시작점 `0`부터 `N-16`까지 총 `N-15`개의 겹치는 구간을 만든다. 시연 전체 길이를 같게 맞추거나 패딩하지 않는다. 길이 16 미만의 시연은 제외한다.
  - `WindowSampler`는 각 시연 안에서 16행이 모두 들어가는 시작점만 허용하므로 서로 다른 시연을 하나의 시퀀스로 연결하지 않는다. 현재 데이터는 모든 시연이 16행 이상이며 학습 구간은 390,518개, 검증 구간은 42,868개다.

- 학습 방법:
  - 백본은 Temporal U-Net이며 `dim=32`, `dim_mults=(1, 4, 8)`, attention 없음이다. Spectral Normalization과 물리 제약 손실은 사용하지 않는다.
  - 정규화된 실제 시퀀스를 `X₁`, 같은 shape의 표준정규 노이즈를 `X₀`로 두고 `τ ~ Uniform(0, 1)`을 뽑는다. CFM은 `Xτ=(1-τ)X₀+τX₁`에서 목표 벡터장 `X₁-X₀`를 예측하도록 MSE로 학습한다. 첫 상태는 `apply_conditioning`으로 실제 조건 `s₀`로 덮어쓴다. 이는 관측 조건을 주는 처리이며 물리 제약 보정은 아니다.
  - 매 업데이트마다 전체 학습 구간에서 32개를 복원 추출한다. 긴 시연은 가능한 구간이 많으므로 더 자주 선택될 수 있다.
  - 1,000,000회 업데이트, Adam, 초기 학습률 `2e-4`, 전체 업데이트에 걸친 단일 cosine 감소, weight decay 0, EMA decay `0.995`, seed 42를 사용한다.
  - 검증은 seed 1234로 고정한 8개 배치(각 32개 구간)의 FM 손실 평균을 계산한다. 전체 검증 구간을 전수 평가한 값은 아니다. 최종 EMA 검증 손실은 `0.093952`다.
  - 설정은 [`config.json`](../fm_baseline/results/pushing_baseline/config.json), 정규화 통계는 `normalizer.npz`, 학습 기록은 `metrics.csv`, 평가용 EMA 가중치는 `baseline_ema.pt`에 저장되어 있다.

- Sampling 과정:
  1. 시뮬레이터에서 최신 실제 손·블록 상태를 읽고, 현재 목표 손 XY와 결합해 12차원 관측을 구성한다. 평가 코드는 `env.step()`의 반환 관측 대신 장면에서 직접 읽은 상태를 사용한다.
  2. 학습 시 저장한 통계로 관측을 정규화하고, `(1, 16, 14)`의 표준정규 노이즈를 만든다. 첫 시점의 상태 12차원을 현재 관측으로 고정한다.
  3. `ConditionedODESolver`의 Euler 적분을 10회 수행해 시퀀스를 생성한다. 적분 중 첫 상태의 변화량은 0으로 고정한다. `value=None`이며 물리 제약 보정은 없다.
  4. 생성 결과를 `x=x_norm*scale+center`로 역정규화한다. 16개 행동 중 앞 8개를 순서대로 실행한 뒤 최신 상태를 읽어 다시 생성한다.
  5. 각 행동은 `다음 목표 XY = 이전 목표 XY + 예측 행동`으로 누적한다. 초기 목표 XY와 고정 높이는 리셋 직후 실제 손 위치에서 가져오며, 환경에는 `[목표 x, 목표 y, 고정 z, 0, 1, 0, 0]`의 7차원 위치·자세 명령을 전달한다. 행동 클리핑은 적용하지 않는다.

  저장된 본 평가는 `execute_steps=8`이다. `eval_pushing.py`의 기본값은 1이므로 재현 시 `--execute-steps 8`을 명시해야 한다.

- 평가 기준:
  - **오프라인 생성 검사:** [`sample.py`](../fm_baseline/sample.py)가 기본적으로 검증 구간 256개를 선택해 shape·유한값·첫 상태 유지 오차를 확인한다. 첫 행동 및 전체 구간 행동 RMSE를 0 행동·선택 split의 평균 행동 기준선과 비교하고, 이후 상태 RMSE를 첫 상태 유지 기준선과 비교한다. 이 RMSE는 시연과의 차이이며 작업 성공률과 별개다.
  - **시뮬레이터 평가:** [`eval_pushing.py`](../fm_baseline/eval_pushing.py)가 공식 `test_contexts.pkl`의 앞 30개 초기 조건에서 각각 4회, 총 120회 실행한다. 최대 400스텝이며, 두 블록이 목표 5cm 이내에 도달하는 환경의 `info['success']`를 성공 기준으로 사용한다.
  - **다양성:** 같은 초기 조건에서 성공한 rollout의 환경 제공 모드 4종 분포로 엔트로피를 계산하고 `log(4)`로 정규화한 뒤 초기 조건별로 평균한다. 성공 rollout이 없는 초기 조건의 기여는 0이다. 점수는 `0.5 × (성공률 + 엔트로피)`다.
  - **저장된 결과:** 성공률 **90.83% (109/120)**, 엔트로피 **0.4912**, 점수 **0.6998**, 종료 시 평균 블록–목표 거리 **0.04353m**, 평균 실행 길이 **237.52스텝**이다. 근거: [`eval_exec8_main_results.json`](../fm_baseline/results/pushing_baseline/eval_exec8_main_results.json).

## 2.2. Inserting

- 모델의 입력과 출력 의미와 차원:
  - 한 시점의 데이터는 `[행동 2차원, 상태 16차원]` 순서의 18차원 벡터다. 상태는 목표 손 XY, 실제 손 XY, 세 블록 각각의 `x, y, sin(yaw), cos(yaw)`이며 순서는 1.2절과 같다.
  - 학습 배치는 `(32, 16, 18)`, 첫 상태 조건은 `(32, 16)`이다. Pushing과 동일하게 신경망은 생성 시간 `τ`와 노이즈가 섞인 시퀀스를 받아 `(32, 16, 18)`의 벡터장을 출력한다.
  - 적분 후 최종 생성 결과는 16시점의 상태·행동 시퀀스다. 제어에는 앞 2차원의 목표 손 XY 변화량만 사용한다. 목표 구역·장벽 배치는 별도 조건으로 입력하지 않는다.

- 데이터 전처리 방법:
  - **NPZ 생성 단계:** [`prepare_inserting.py`](../preprocess/prepare_inserting.py)가 세 블록의 방향을 sin/cos로 표현하고 목표 손 XY 차분을 행동으로 저장한다. 목표 손 높이·방향, 목표 구역 위치의 고정 여부와 기록 간격도 검사한다.
  - 초기 조건 context를 소수 6자리로 반올림한 뒤 SHA-256으로 그룹화하고, seed 42로 그룹의 약 10%를 검증에 배정한다. 같은 그룹은 같은 split에 속한다. 결과는 학습 718개, 검증 82개 시연이며 공식 분할이 아니다.
  - [`verify_processed.py`](../preprocess/verify_processed.py)는 Inserting 저장 파일의 차원·유한값·시간 연결·sin/cos·행동 정의와 분할 간 파일 및 context 그룹 중복을 검사한다. 이 스크립트의 대상은 Stacking과 Inserting이며, Pushing 검사는 `prepare_pushing.py` 안에 있다.
  - **학습 로딩 단계:** Pushing과 같은 `load_split()`, `Normalizer`, `WindowSampler`를 사용한다. 학습 데이터만으로 18개 채널의 정규화 통계를 계산하고 검증·추론에 재사용한다. `obs`, `actions`만 읽으며 패딩·클리핑·제약 라벨 생성은 하지 않는다.
  - 시연 길이는 그대로 두고 각 시연 내부에서 길이 16의 구간을 추출한다. 시연 경계를 넘는 구간은 없으며, 학습 구간은 701,138개, 검증 구간은 79,249개다.
  - NPZ의 context 누락은 학습 구간 구성과 관계없다. 환경 초기화에는 별도 [`contexts/inserting_val.pkl`](../fm_baseline/contexts/inserting_val.pkl)을 사용하며, 필요한 항목이 없으면 원본 pkl에서 읽는다.

- 학습 방법:
  - 백본은 Temporal U-Net이며 `dim=64`, `dim_mults=(1, 2, 4, 8)`, attention 없음이다. Pushing보다 폭과 단계 수를 키운 모델을 사용한다. Spectral Normalization과 물리 제약 손실은 사용하지 않는다.
  - CFM의 노이즈·데이터 보간, 벡터장 MSE 학습, 첫 상태 조건 고정, 구간 복원 추출 방식은 Pushing과 같다.
  - 1,000,000회 업데이트, 배치 32, Adam, 초기 학습률 `2e-4`, 단일 cosine 감소, weight decay 0, EMA decay `0.995`, seed 42다.
  - 검증은 seed 1234의 8개 배치 손실 평균이며 최종 EMA 검증 손실은 `0.100695`다. 설정은 [`config.json`](../fm_baseline/results/inserting_baseline/config.json), 통계·로그·EMA 가중치는 같은 폴더의 `normalizer.npz`, `metrics.csv`, `baseline_ema.pt`에 있다.

- Sampling 과정:
  1. 최신 실제 손·세 블록 상태와 현재 목표 손 XY로 16차원 관측을 구성하고 정규화한다.
  2. `(1, 16, 18)`의 표준정규 노이즈에서 첫 상태를 관측으로 고정하고, Pushing과 같은 Euler ODE 적분 10회로 상태·행동 시퀀스를 생성한다.
  3. 역정규화한 앞 8개 행동을 순서대로 실행한 뒤 다시 관측하고 생성한다. 목표 XY를 누적하고 리셋 직후 실제 손 높이와 `[0, 1, 0, 0]` 방향을 붙여 7차원 명령을 만든다. 물리 제약 보정·행동 클리핑은 하지 않는다.

- 평가 기준:
  - **오프라인 생성 검사:** Pushing과 같은 `sample.py`로 형태·유한값·조건 유지, 행동·상태 RMSE 및 기준선을 검사한다.
  - **시뮬레이터 평가:** [`eval_inserting.py`](../fm_baseline/eval_inserting.py)가 검증 시연 82개의 초기 배치에서 실행한다. 저장된 본 평가는 seed 0과 1에서 각각 배치당 2회 실행한 결과를 합친 것으로, 총 **328회(82 × 4)**다. 최대 2,000스텝이며, 세 블록이 각각 목표 1cm 이내에 도달하는 환경의 `info['success']`를 사용한다.
  - **다양성·부분 진척:** 환경 제공 모드 6종의 성공 rollout 분포를 `log(6)`으로 정규화해 엔트로피를 구한다. 합산 결과의 점수는 `0.5 × (성공률 + 엔트로피)`다. `eval_inserting.py`의 개별 결과에는 점수 필드가 없으며, 부분 진척은 환경의 블록별 성공 플래그 합계로 계산한다. 각 블록의 플래그와 최종 전체 성공 판정은 다를 수 있으므로 `three_box_rate`와 `success_rate`를 구분한다.
  - **저장된 결과:** 성공률 **81.40% (267/328)**, 엔트로피 **0.3511**, 점수 **0.5826**, 종료 시 평균 블록–목표 거리 **0.03322m**, 평균 실행 길이 **1,345.13스텝**이다. 블록 성공 플래그가 1개 이상·2개 이상·3개인 비율은 각각 **97.56%·91.77%·82.32%**다. 근거: [`eval_inserting_val_exec8_main_combined.json`](../fm_baseline/results/inserting_baseline/eval_inserting_val_exec8_main_combined.json).

두 태스크는 평가 초기 조건, 블록 수, 허용 오차, 최대 스텝이 다르다. 모델·제약 실험의 비교는 같은 태스크와 같은 평가 조건에서 수행한다. 현재 평가 코드에는 별도 물리 제약 위반율 계산이 없다.
