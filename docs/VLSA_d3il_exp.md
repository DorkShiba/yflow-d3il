### 0.2 적용할 직사각형 울타리

아래 수치는 **연구에서 정한 가상 작업 영역**이며 원본 환경이 강제하는 벽이나 도달 가능성 증명이 아니다. 원본 초기·목표 위치를 포함하고 상판 안에 있으며, 위 학습 시연의 손 좌표를 모두 포함하도록 여유 있는 둥근 수치로 정했다. 물리 벽을 추가하거나 환경 형상을 바꾸지 않는다.

| 항목 | Pushing | Inserting |
|---|---|---|
| 외곽 x 범위 (m) | `[0.20, 0.85]` | `[0.00, 0.85]` |
| 외곽 y 범위 (m) | `[-0.40, 0.50]` | `[-0.40, 0.75]` |
| 경계 안쪽 여유 margin | `0.01 m` | `0.01 m` |

| 축별 목표 위치 증분 한계 | `±0.01 m/제어 step` | `±0.01 m/제어 step` |
| 전체 XY 목표 증분 길이 한계 | `0.012 m/제어 step` | `0.012 m/제어 step` |
| 허용 접촉 | 푸셔–두 블록 | 푸셔–세 블록 및 기존 작업의 접촉 |
| 이번에 추가하지 않는 제약 | 블록 보호·추종 거리·목표 도달 | 내부 장벽 회피·블록 보호·회전·깊이·접촉력 |

`±0.01 m`는 원본 환경의 선언된 XY 행동 범위를 참고해 정한 실험용 명령 한계다. 물리적 안전 속도나 원본 7차원 위치 명령의 자동 clipping이라고 주장하지 않는다. margin은 목표 TCP 중심에 대한 설계 여유이며 실제 푸셔 반경을 측정한 값이 아니다.

Inserting의 울타리를 Pushing과 같게 만들면 상단 목표와 접근 궤적을 제한할 수 있으므로 상한을 별도로 둔다. 원래 미로의 내부 벽은 그대로 존재하지만 이번 QP에 포함하지 않는다. 기존 블록을 회피 장애물로 등록하지 않는다.

### 0.3 실행 직전 QP와 보장의 범위

현재 누적 목표 XY를 $q$, 명목 목표 증분을 $\Delta_{nom}$, 안쪽 여유를 적용한 경계를 $\ell,u$라 둔다. 실행할 각 행동마다 다음 QP를 푼다.

$$
\min_{\Delta\in\mathbb R^2}\frac12\|\Delta-\Delta_{nom}\|^2,
\qquad
\ell\le q+\Delta\le u,\qquad -0.01\le\Delta_x,\Delta_y\le0.01,\qquad \|\Delta\|_2\le0.012.
$$

직사각형의 네 안전 여유는 `[q_x-l_x, u_x-q_x, q_y-l_y, u_y-q_y]`다. 명령 적분기 $q_{k+1}=q_k+\Delta_k$의 다음 상태에 선형 부등식을 직접 부과한다. 이 버전에는 실제 속도 근사나 `gamma`가 필요하지 않으며 AEGIS의 타원체 연속시간 CBF 재현과 구분한다.

2026-10-23부터 `--vlsa`의 기본은 **울타리+L2 이동량+축별 한계**다. 길이 한계는 `Δx²+Δy² ≤ R²`이며 이전 행동 대비 변화량 제한이 아니다. 원판을 추가한 문제는 엄밀히 볼록 QCQP/SOCP이며 box+원판 교집합에 대한 스칼라 KKT 승수 이분법으로 공동 최소 수정 해를 구한다. 기존 선형 QP에 단순 순차 clipping을 붙이는 방식은 사용하지 않는다.

학습 행동 길이의 최대는 Pushing 10.7932mm, Inserting 10.9675mm다. 두 태스크 모두 R=12mm면 학습 행동의 초과 비율은 0%이며, R=10mm면 각각 0.4282%, 1.7712%다. 따라서 12mm를 초기 기본값으로 두고 10mm를 더 강한 validation 비교값으로 사용한다. 이 기준은 시연 보존을 고려한 실험 초기값이며 물리적 안전 한계나 검증된 최적값이 아니다.

- VLSA가 켜져 있으면 `vlsa_constraint()`를 **각 행동 실행 직전** 호출한다. 생성 16개·실행 8개 설정을 유지하고 8개 각각을 검사한다.
- $q$는 이전에 실제로 전달한 수정 명령을 누적한 값이다. 수정 후 $q$를 다음 정책 관측에도 반영한다. 실제 손 위치를 목표 위치와 혼동하지 않는다.
- 최소 수정 해는 사각형·축별 증분 box·이동량 원판의 교집합으로 투영한 값이다. box-only clipping 해, 원판-only 방사 투영 해, 독립적인 수치 최적화 결과와 대조해 검증한다.
- 초기 목표 위치가 영역 밖이면 `initial_unsafe`, 상충 제약으로 해가 없으면 `infeasible`로 기록하고 에피소드를 실패 처리한다. 목표를 순간적으로 안쪽으로 이동시키는 복구는 구현하지 않는다.
- 이 제약은 **전달할 목표 TCP 위치**의 영역 유지만 보장한다. 실제 손의 추종 오차·관성·내부 미세 step 이탈, 전체 로봇 링크, 블록 이탈, 미로 벽 충돌은 보장하지 않는다.
- 실제 손은 초기화 직후와 각 제어 step 후 별도로 측정해 영역 위반을 기록한다. 내부 step 전체를 계측하지 않았으므로 이 지표를 연속시간 안전성으로 표현하지 않는다.

### 0.4 설정·평가·구현 범위

`configs/pushing.yaml`, `configs/inserting.yaml`의 `vlsa.geometry=rectangle`, `vlsa.workspace` 네 경계, `margin_m=0.01`, `command_delta_limit_m=0.01`로 위 명세를 저장한다. 기본 `enabled=false`를 유지하고 `--vlsa`/`--no-vlsa`로 비교한다. 외부 원형 장애물은 `obstacles=[]`로 두며, 원형 CBF 수치 기능은 별도로 보존한다. 원형 장애물의 실제 환경 연결은 추종·기하 감사 전까지 계속 차단한다.

`workspace_enabled=true`, `action_norm_enabled=true`, `max_step_displacement_m=0.012`가 기본이다. 각 하위 flag는 `--set`으로 독립 변경할 수 있고, VLSA on에서 둘 다 false면 축별 한계만 남는다. 원형 CBF 수치 모드는 `action_norm_enabled=false`를 명시한다. 원형 CBF와 이동량 원판의 공동 최적화는 이번 지원 범위가 아니다. 실행 로그에는 명목·최종 실행 행동의 길이, 원판 잔차(m), 반복 수를 기록한다. 명목 초과율은 모든 행동 시도, 실행 초과율·개입률은 실제 실행된 행동만 분모로 사용한다.

기존 성공률·엔트로피 외에 에피소드별 목표 영역 위반율, 제어 시점 실제 손 영역 위반율, 목표 영역을 지킨 성공률을 각각 보고한다. 로그에는 경계별 목표·실제 여유, QP 잔차, 수정량, 실패 원인을 남긴다. 물리 금지 접촉의 Safe Success Rate는 계측이 없으면 `null`이다. 정지 비교군은 같은 QP가 명목 행동 수정을 요구하면 목표 증분을 0으로 둔다. 정상 초기 목표에서 0 증분은 가상 울타리를 유지하지만 실제 운동 정지를 보장하지 않는다.

코드는 이 절을 작성한 뒤 구현한다. D3IL 설치가 없는 현재 환경에서는 수치·모의 rollout·기존 체크포인트 호환성을 검증하고, 실제 시뮬레이터 평가를 완료했다고 보고하지 않는다.

## 1. 연구 개요

### 1.1 연구 질문

**언어 입력이 없는 flow matching 기반 정책에, 추가 정책 학습 없이 최종 행동 최적화를 적용하면 접촉이 필요한 조작 작업에서도 금지된 충돌을 줄이면서 작업 수행 능력을 유지할 수 있는가?**

세부 질문은 다음과 같다.

1. CBF-QP 구현이 제약을 만족하는 최소 수정 행동을 실제로 반환하는가?
2. 위치 명령을 사용하는 실행 환경에서도 실제 운동 궤적이 안전 조건을 유지하는가?
3. Pushing과 inserting에서 필요한 접촉과 금지된 충돌을 구분하면 작업 수행을 유지할 수 있는가?
4. 안전 필터가 정체, 분포 이동, 행동 다양성 감소를 유발하는가?
5. 정확한 상태 정보를 사용하는 조건에서 검증한 효과가 추종 오차·지연·기하 오차 아래에서도 유지되는가?

### 1.2 제안 시스템

```text
손·블록 상태 (현재 정책) / 영상 입력은 후속 확장
                 |
        Flow Matching 정책
          (학습 후 고정)
                 |
          명목 행동 a_nom
                 |
    물리 단위 복원 / 행동 인터페이스 변환
                 |
           CBF-QP 안전 필터 <--- 시뮬레이터 상태·형상
                 |
          안전 명령 a_safe
                 |
          저수준 제어기 / 환경
                 |
          실제 상태 재관측
```

현재 실험의 정책은 상태 입력을 사용하고, 울타리는 명시한 세계 좌표 경계를 사용한다. 후속 장애물 실험에서 필터에 시뮬레이터의 정확한 상태·형상을 제공하면 이를 **oracle geometry 조건**으로 명시한다. 현재 실험은 영상 기반 장애물 인식 성능을 평가하지 않는다.

### 1.3 Training-free의 의미

기본 flow matching 정책은 시연 데이터로 학습한다. 이후 안전 필터를 추가할 때 정책의 가중치를 수정하거나 추가 안전 데이터로 재학습하지 않는다. 따라서 “전체 시스템이 학습 없이 동작한다”가 아니라 **“학습된 정책에 추가 학습 없이 안전 필터를 적용한다”**고 표현한다.

## 2. VLSA 논문 상세 설명

### 2.1 문제의식

VLA는 영상과 언어 지시를 행동으로 연결하지만, 작업 성공을 학습했다고 해서 물리적 비충돌이 보장되는 것은 아니다. 학습에서 보지 못한 물체가 경로에 놓이면 명목 행동을 그대로 실행하다 충돌할 수 있다.

안전 보상을 추가하여 정책을 재학습하는 방법은 가능하지만, 추가 데이터와 계산이 필요하고 안전이 벌점 형태의 목적에 머물 수 있다. VLSA는 기존 정책 뒤에 명시적 안전 제약을 두어 실행 행동을 수정한다.

### 2.2 VLSA와 AEGIS

- **VLSA**: Vision-Language-Safe Action. 기존 VLA 행동 출력 뒤에 Safety Constraint Layer를 추가하는 구조이다.
- **AEGIS**: Action Execution Guarded by Invariant Safety. 논문이 제안한 VLSA의 구체적인 구현이다.

AEGIS는 크게 두 모듈로 구성된다.

| 모듈 | 입력 | 기능 | 출력 |
|---|---|---|---|
| Vision-language safety assessment | 영상·언어 지시·깊이 | 회피할 물체를 선택하고 공간적으로 추정 | 장애물 기하 정보 |
| Safety-guaranteed control | 기하 정보·명목 행동 | CBF 제약 아래 행동을 최소 수정 | 실행할 안전 행동 |

### 2.3 언어의 역할: 접촉 대상과 장애물 구분

“그릇을 집어 접시에 놓기”에서는 그릇과 접시에 접근해야 한다. 모든 물체를 장애물로 처리하면 작업을 수행할 수 없다. AEGIS는 영상과 작업 지시를 VLM에 제공하여 가장 중요한 비로봇 장애물 하나를 선택하고, 색·종류 등을 포함한 이름을 출력하게 한다.

따라서 원 논문은 단순히 가장 가까운 물체를 고르는 방법이 아니다. 또한 현재 선택한 장애물 하나에 대한 제약을 구성하므로, 환경의 모든 장애물과 전체 로봇을 동시에 보호하는 시스템으로 해석하면 안 된다.

본 실험에서는 이 언어 기반 역할 구분을 환경 메타데이터의 접촉 허용 목록으로 대체한다. 단일 작업이면 언어를 제외할 수 있지만, 영상만으로 목표를 구분할 수 없는 다중 작업에서는 목표 위치 또는 task ID 등을 제공해야 한다.

### 2.4 영상에서 3차원 기하로의 변환

원 논문은 선택된 물체 이름과 영상을 Grounding DINO에 제공해 2차원 bounding box를 얻는다. 깊이 정보를 사용해 해당 영역을 3차원으로 역투영하고, 서로 다른 시점의 점군을 세계 좌표계로 변환하여 합친다.

픽셀 좌표를 $(u,v)$, 깊이를 $d$, 내부 파라미터를 $K$라 하면:

$$
p_{cam}=dK^{-1}[u,v,1]^\top.
$$

카메라 외부 파라미터로 이를 세계 좌표계에 옮긴다. 이후 작업 공간 필터링, 중심으로부터 먼 점 제거, 클러스터링을 적용한다.

중요한 제한은 **필터링된 점군을 감싸는 형상이 실제 물체 전체를 포함한다는 보장이 자동으로 생기지 않는다**는 것이다. 과도한 필터링이나 가림은 장애물 크기를 과소평가하게 만들 수 있다.

### 2.5 타원체 모델

AEGIS는 장애물 점군을 최소 부피 외접 타원체(MVEE)로 근사하고, 말단 장치도 타원체로 감싼다. 복잡한 점군 사이의 충돌 판단을 두 타원체의 분리 문제로 바꾸는 것이다.

말단 타원체의 중심은 말단 기준 위치와 구조적 오프셋으로 연결된다.

$$
p_{ep}=p_{ef}+R_{ef}\Delta p.
$$

따라서 말단 회전은 타원체의 방향뿐 아니라 오프셋에 따른 중심에도 영향을 줄 수 있다. 병진만 고려하는 경우와 병진·회전을 함께 고려하는 경우를 구분해야 한다.

### 2.6 안전 함수와 가상 분리 평면

안전 상태 집합은 다음과 같이 정의한다.

$$
\mathcal C=\{x\mid h(x)\geq0\}.
$$

직관적으로 $h$는 안전 여유이다. 원 논문에서는 말단 타원체의 접평면과 장애물 타원체 사이의 부호 있는 거리를 이용해 $h$를 구성한다. 평면이 두 타원체를 분리하면 비충돌을 인증할 수 있다.

접평면을 조절하기 위해 단위 구면 위의 가상 상태 $p_s$를 도입한다. 이는 실제 관절이 아니라 기하학적 보조 변수이다. 로봇이 이동할 때 분리 평면도 회전시켜, 고정된 평면이 유발하는 과도한 보수성을 줄인다. 논문은 $p_s$에 대해 $h$를 최대화하면 두 타원체 사이의 최단 거리를 얻는다고 설명한다. 일반적인 $p_s$에서 $h$를 항상 정확한 최단 거리로 간주해서는 안 된다.

### 2.7 CBF 조건

현재 비충돌 상태라는 사실만으로 미래 비충돌을 보장할 수 없다. 따라서 안전 여유의 변화율을 제한한다.

$$
\dot h(x,u)\geq-\alpha(h(x)).
$$

일반적으로 $\alpha(h)=\gamma h$, $\gamma>0$를 사용할 수 있다. 논문은 실험에서 $\alpha(h)=10h$를 사용한다.

- $h$가 크면 어느 정도 접근을 허용한다.
- $h$가 작아지면 안전 여유가 감소하는 속도를 제한한다.
- 경계 $h=0$에서는 $\dot h\geq0$을 요구한다.

이는 장애물 주변에서 모든 행동을 정지시키는 조건이 아니다. 장애물 옆으로 움직이는 등 안전한 방향의 행동은 허용할 수 있다. 또한 $\gamma$가 커지면 같은 양의 $h$에서 더 빠른 접근을 허용하므로, 큰 $\gamma$를 무조건 더 보수적인 설정으로 해석하지 않는다.

### 2.8 최종 행동 최적화

원 논문은 명목 행동과의 차이를 최소화하면서 안전 조건을 만족시키는 행동을 구한다.

$$
u_{safe}=\arg\min_u\|u-u_{vla}\|^2
\quad\text{s.t.}\quad
\dot h(x,u)\geq-\alpha(h(x)).
$$

원 논문의 행동 표현은 말단 병진 속도, 회전 속도, 그리퍼 명령으로 구성된다. 이것은 모든 관절별 정책을 독립적으로 최적화한다는 뜻이 아니다.

제어 입력에 대해 선형인 운동 모델에서 CBF 조건을 선형 부등식으로 표현하면, 이차 목적함수를 가진 QP로 풀 수 있다. 안전한 명목 행동은 그대로 통과하고 위험한 행동만 수정된다. 가상 분리 평면을 사용하는 구체적 구현에서는 그 보조 상태와 제어도 함께 확인해야 한다.

### 2.9 Flow matching과의 관계

원 논문은 flow matching 기반 $\pi_{0.5}$를 기본 정책으로 사용한다. 하지만 flow matching의 학습 목적함수나 내부 생성 벡터장을 안전 제약으로 수정하는 방법은 아니다.

```text
잡음 -> Flow matching 행동 생성 -> 명목 행동 -> CBF-QP -> 실행
```

생성 과정의 내부 시간과 실제 로봇 운동 시간을 구분해야 한다. 본 연구도 생성된 행동을 실행 직전에 수정하는 구조를 기본으로 한다. Flow 생성 중 제약을 적용하는 연구는 별도 확장으로 취급한다.

### 2.10 실험 결과와 보장의 범위

첨부 PDF v2의 SafeLIBERO 실험은 32개 시나리오, 총 1,600개 에피소드로 구성된다. Table I의 전체 행동 공간 평균은 다음과 같다.

| 방법 | 충돌 회피율 CAR | 작업 성공률 TSR |
|---|---:|---:|
| 기본 $\pi_{0.5}$ | 17.1% | 57.8% |
| AEGIS | 68.9% | 67.5% |

증가는 각각 51.8%포인트와 9.7%포인트이다. 모든 작업군에서 성공률이 증가하는 것은 아니다. Long 작업군의 전체 행동 공간 성공률은 감소한다.

이론적 비충돌 보장은 정확한 장애물 판단, 완전한 기하 표현과 외접 형상 등의 가정을 전제로 한다. CBF 불변성은 안전한 초기 상태, 적절한 정규성 및 제약을 만족하는 제어의 실행을 요구한다. 현재 방법은 말단 장치를 제약하므로 다른 링크의 충돌까지 보장하지 않는다.

안전 필터로 인해 정책이 학습에서 보지 못한 상태로 이동하는 **safety-induced distribution shift**도 발생할 수 있다. CBF는 안전 유지 장치이지 목표 도달을 보장하는 전역 계획기가 아니다.

## 3. 본 실험의 범위와 주장

| 단계 | 내용 | 가능한 주장 |
|---|---|---|
| A | 원·평면 기반 CBF + 고정 정책 | 최종 CBF-QP 원리의 정확성·효과 검증 |
| B | Pushing/Inserting + 외부 장애물 | 접촉 작업으로의 안전 필터 전이 |
| C | 원 논문 타원체·가상 분리 평면 구현 | AEGIS 제어 모듈의 기하학적 재현 |
| D | 삽입 정렬·깊이별 제약 | 접촉 작업에 맞춘 안전 정의 확장 |
| E | 물체 동역학·접촉력·인지 오차 | 별도 모델과 검증이 필요한 후속 연구 |

현재 최소 실행 범위는 0절의 목표 위치 직사각형 울타리다. 표의 A+B 외부 장애물 실험은 후속 단계이며, C와 D는 별도 확장이다. 목표 위치 울타리만으로 실제 손의 CBF 안전성이나 AEGIS 전체 재현을 주장하지 않는다.

## 4. 구현 전 확인 사항

### 4.1 환경·데이터 감사

- D3IL 저장소 commit, MuJoCo 및 의존성 버전을 고정한다.
- Pushing과 inserting의 실제 관측·행동 차원, 제어 주기, action repeat, 저수준 제어기를 각각 확인한다.
- 사용하는 inserting 구현과 데이터 경로를 직접 확인한다. Pushing 설정이 동일하게 적용된다고 가정하지 않는다.
- 영상 데이터 제공 여부와 카메라 설정을 확인한다. 필요한 경우 데이터 생성을 별도 작업으로 기록한다.
- 목표가 관측에 포함되는지, task ID 또는 목표 좌표가 추가로 필요한지 확인한다.
- 명목 정책의 입력에 이전 명령 위치가 들어가는 경우, 필터 수정 이후 그 상태를 어떤 값으로 갱신하는지 확인한다.

공식 pushing 평가 코드에서는 정책 출력을 이전 명령 위치에 더해 다음 명령을 구성하는 경로가 존재한다. 따라서 속도 입력이라는 가정을 먼저 두지 않는다.

### 4.2 명령 좌표와 물리 단위

정규화된 행동은 물리 단위로 복원한 후 안전 계산에 사용한다. 필요한 경우 필터 출력만 다시 환경 인터페이스로 변환한다. 위치·회전이 함께 있는 목적함수는 단위와 스케일이 다르므로 $W$로 가중치를 명시한다.

위치 증분을 속도로 변환하는 $v\approx\Delta p/\Delta t$는 이상적 근사이다. 실제 제어기의 추종 궤적과 속도를 측정해 이 근사가 유효한지 확인한다.

### 4.3 접촉 명세

환경 geometry 쌍별로 다음 항목을 작성한다.

```text
pair_id / 허용 여부 / 적용 작업 단계 / 거리 여유 / 판정 방법
```

접촉 허용은 의미적 분류이다. 허용 접촉이라는 이유만으로 충격이나 힘의 크기까지 안전하다고 간주하지 않는다.

## 5. 정책 학습 계획

### 5.1 기본 정책

- 입력: 현재는 손·블록의 상태 관측(Pushing 12차원, Inserting 16차원). RGB는 후속 확장이다.
- 출력: 환경 인터페이스와 일치하는 단일 행동 또는 행동 묶음.
- 학습: 시연 데이터 기반 conditional flow matching.
- 학습 완료 후 정책 가중치 고정.
- 최초에는 작업별 정책을 사용하여 언어 제거에 따른 목표 모호성을 줄인다.

### 5.2 학습·평가 분리

- 공식 분할을 우선 사용하고, train/validation/test context를 분리한다.
- 모델 선택과 CBF 파라미터 조정은 validation에서 수행한다.
- test 결과를 보고 margin, $\gamma$, 장애물 배치를 재조정하지 않는다.
- 현재 기본 실험은 기존 환경과 정책을 유지하고 가상 작업 영역의 명령 제약만 켜고 끈다. 후속 외부 장애물 실험에서는 추가 장애물 자체가 분포 이동임을 명시한다.
- 추가 분석에서는 장애물이 관측에 익숙한 조건을 마련하여, 시각적 분포 이동과 안전 필터 효과를 구분할 수 있다.

### 5.3 행동 묶음 실행

정책이 여러 시점의 행동을 출력해도 각 행동 실행 직전에 최신 상태로 필터를 다시 푼다. 한 번 계산한 제약으로 긴 행동 묶음 전체를 보장한다고 주장하지 않는다.

현재는 baseline과 같은 생성 16개·실행 8개를 사용한다. 재계획 주기 변경은 별도 절제로 분리한다.

## 6. 안전 필터 수식과 수치 검증

### 6.1 기본 QP

제어 모델을 $\dot x=f(x)+g(x)u$라 하면:

$$
\begin{aligned}
u^*=\arg\min_u\;&\frac12(u-u_{nom})^\top W(u-u_{nom})\\
\text{s.t. }&L_fh_i(x)+L_gh_i(x)u\geq-\gamma_i h_i(x),\quad \forall i,\\
&u_{min}\leq u\leq u_{max}.
\end{aligned}
$$

$W\succ0$일 때 해가 존재하면 목적함수는 엄격히 볼록하여 제어 입력 해가 유일하다. 다중 장애물과 입력 한계를 포함하면 실행 가능한 행동이 없을 수 있다.

### 6.2 첫 검증용 평면 원형 장애물

푸셔 위치 $p$, 고정 장애물 중심 $c_i$, 합산 반경과 margin을 $R_i$라 두면:

$$
h_i(p)=\|p-c_i\|^2-R_i^2.
$$

직접 속도 제어 $\dot p=v$에서는:

$$
2(p-c_i)^\top v\geq-\gamma_i h_i(p).
$$

이는 초기 구현용 단순화이며 AEGIS의 타원체 CBF를 그대로 재현한 것은 아니다.

### 6.3 해석해와의 비교

다른 제약 없이 $a^\top u\geq b$ 하나만 있는 유클리드 투영 문제는 $a\neq0$일 때:

$$
u^*=\begin{cases}
u_0,&a^\top u_0\geq b,\\
u_0+\dfrac{b-a^\top u_0}{\|a\|^2}a,&a^\top u_0<b.
\end{cases}
$$

무작위 입력과 경계 인근 입력에서 QP 해를 이 값과 대조한다. $a=0$에서는 $b\leq0$이면 제약이 항상 만족되고 $b>0$이면 불가능하므로 별도로 처리한다.

### 6.4 검증 항목

1. 안전한 명목 입력은 허용 오차 안에서 그대로 통과하는가?
2. 위험 입력의 수정 결과가 제약을 만족하는가?
3. 해석해가 있는 경우 최소 수정 해와 일치하는가?
4. 다중 제약·입력 한계에서 solver 상태와 잔차가 올바르게 기록되는가?
5. 실제 시뮬레이션 미세 시간 간격에서 최소 거리가 유지되는가?
6. 불가능한 경우를 숨기지 않고 실패 또는 별도 복구로 집계하는가?

연속시간 CBF 부등식을 제어 시점마다 만족한다고 유한 샘플 간격 전체의 안전이 자동 보장되지는 않는다. 실제 내부 step의 거리·접촉을 측정하고, 필요하면 margin·추종 오차 한계·샘플드데이터 설계를 추가한다. 이를 도입하지 않았다면 경험적 안전성 결과로 한정한다.

### 6.5 예외와 복구

- NaN, solver 실패, 입력 한계 충돌, 초기 $h<0$을 구분한다.
- 정지 명령이 항상 안전하다고 가정하지 않는다. 동역학·접촉 중에는 정지 목표에도 관성이나 추종이 남을 수 있다.
- 불가능 상태는 우선 에피소드를 실패로 종료하고 로그를 남긴다. 별도 복구 정책을 쓰면 별도 실험 조건으로 보고한다.
- 안전 제약에 slack을 사용하면 그 위반량을 기록하며 엄격한 제약 보장을 주장하지 않는다.

## 7. Pushing 실험

### 7.0 현재 실험 P-W: 목표 손의 직사각형 작업 영역 유지

0.2절의 Pushing 경계와 0.3절 QP를 사용한다. 두 블록을 미는 접촉을 유지하고 외부 물리 장애물은 추가하지 않는다. 성공률과 목표 좌표·제어 시점 실제 손의 영역 위반율을 각각 비교한다. 목표 달성 여부는 기존 환경의 두 블록 목표 도달 판정을 그대로 따른다.

### 7.1 후속 실험 P1: 푸셔의 외부 장애물 회피

기존 블록·목표를 유지하고 고정 장애물을 추가한다. 푸셔–블록 접촉은 허용하고 푸셔–추가 장애물 접촉은 금지한다. 일차 안전 대상은 푸셔이며, 블록의 충돌은 별도 지표로 기록한다.

| 조건 | 배치 의도 |
|---|---|
| P0 | 추가 장애물 없음: 필터의 불필요한 개입 확인 |
| P1 | 명목 경로 주변: 안전 여유 영향 확인 |
| P2 | 명목 경로를 가로막지만 우회 가능한 배치 |
| P3 | 좁지만 모델상 실행 가능한 통로 |
| P4 | 의도적으로 실행 불가능한 배치: 실패 처리 확인 |

P4는 성공률 향상을 기대하는 주 실험과 분리한다. P1–P3도 통로 폭과 형상 검사를 통해 작업 가능성을 확인한다.

### 7.2 실험 P2: 다중 장애물

P1이 동작한 후 장애물을 여러 개 배치하고 제약을 동시에 적용한다. 이는 장애물 하나를 고르는 원 논문의 기본 설정에 대한 확장이다. 최근접 장애물 하나만 적용하는 변형과 모든 지정 장애물을 적용하는 변형을 비교할 수 있다.

### 7.3 후속 실험: 블록 보호

푸셔 보호만으로 밀리는 블록의 안전은 보장되지 않는다. 블록–장애물까지 제약하려면 접촉 상태와 마찰을 포함하는 물체 운동 모델 또는 예측 모델이 필요하다. 로봇 속도용 CBF를 블록에 그대로 대입하지 않는다.

모델을 학습하면 “기본 정책 추가 학습 없음”은 유지할 수 있지만 “안전 모듈 전체가 학습 없음”이라는 주장은 수정해야 한다.

## 8. Inserting 실험

### 8.0 현재 실험 I-W: 세 블록 작업의 직사각형 작업 영역 유지

0.2절의 Inserting 전용 경계와 0.3절 QP를 사용한다. 현재 작업은 고정 높이에서 세 블록을 미로 사이 목표 위치로 미는 평면 조작이다. Pushing보다 높은 y 상한으로 상단 목표와 접근 경로를 포함한다. 기존 장벽은 환경에 그대로 두며 이번 QP는 내부 장벽 회피를 제약하지 않는다. 성공률·부분 진척·모드와 바깥 영역 위반을 분리해 보고한다.

### 8.1 후속 실험 I1: 외부 장애물 회피

기존 평면 조작 작업 주변에 장애물을 추가한다. 푸셔–블록의 정상적인 접촉은 허용한다. 외부 장애물에 대해서만 먼저 CBF를 적용한다.

이 실험은 세 블록 배치 성공과 주변 장애물 회피의 양립을 평가한다. 푸셔만 보호하면 밀리는 블록과 장애물 사이의 충돌은 보장하지 않으므로 그 범위를 명시한다.

### 8.2 후속: 내부 장벽 형상과 통로 보존

전체 미로를 하나의 외접 타원체로 감싸면 정상 통로까지 금지 공간이 된다. 실제 scene에 등록된 각 장벽의 위치·회전·크기를 읽어 여러 primitive 또는 충돌 거리로 구성해야 한다. 정의만 있고 등록되지 않은 `maze_1`, `maze_2`를 장애물로 추가하지 않는다. 현재 울타리 구현에는 이 제약이 포함되지 않는다.

### 8.3 다른 삽입 환경으로 확장할 경우: 정렬과 깊이에 따른 제약

아래 식은 깊이 제어가 가능한 다른 삽입 환경을 위한 후보이며 현재 고정 높이 D3IL Inserting에 적용하지 않는다. 실제 환경이 허용하는 자유도를 확인한 뒤 적용한다. 회전이 고정된 환경에서 회전 제어 성능을 평가하지 않는다.

| 단계 | 제안 제약 | 전환 조건 예시 |
|---|---|---|
| 접근 | 외부 장애물 회피·속도 한계 | 입구 근처 도달 |
| 정렬 | 측면 오차·가능한 경우 각도 오차 | 정렬 임계값 만족 |
| 삽입 | 깊이별 허용 오차·벽 간섭 제한 | 목표 깊이 도달 |

측면 오차를 $e_\perp$, 깊이를 $z$, 실제 형상에서 유도한 허용 오차를 $c(z)$라 하면 다음 후보를 사용할 수 있다.

$$
h_{align}=c(z)^2-\|e_\perp\|^2.
$$

이에 대한 미분은:

$$
\dot h_{align}=2c(z)c'(z)\dot z-2e_\perp^\top\dot e_\perp.
$$

해당 속도가 제어 입력에 선형으로 연결되는 모델에서 CBF-QP 제약으로 구성한다. 입구 형상에 따른 $c(z)$의 미분 가능성, 프레임 정의, 삽입 물체의 유한 크기와 방향을 확인한다. 안전 집합 밖에서 제약을 갑자기 켜지 않도록 단계 전환 조건을 설계한다.

이 식은 연구용 후보이며 임의의 삽입 형상에 대한 안전 증명이 아니다. 우선 단순한 정렬·삽입 형상에서 검증한다.

### 8.4 후속 실험: 힘과 걸림

접촉력을 측정한다고 바로 선형 CBF 제약을 얻는 것은 아니다. 입력 변화와 접촉력 변화의 관계를 모델링해야 한다. 힘·토크 제한과 걸림 방지는 접촉 모델, 상대 차수, 제어기 종류를 검토하는 별도 확장으로 둔다.

## 9. 비교군과 절제 실험

### 9.1 필수 비교군

| ID | 방법 | 목적 |
|---|---|---|
| B0 | Flow matching 정책 단독 | 기본 성능 |
| B1 | 위험 예측 시 정지하는 필터 | 충돌 감소가 단순 정지 때문인지 확인 |
| B2 | Flow matching + CBF-QP | 주 제안 |

비교군은 동일한 상태 정보, 장애물 형상, 입력 한계, 제어 주기를 사용한다. 정지 필터의 위험 판정도 동일한 예측 조건을 사용하고, 정지 횟수와 복구 규칙을 명시한다.

### 9.2 선택 비교군

- 단순 반발 벡터/인공 퍼텐셜 기반 수정.
- AEGIS 타원체 CBF와 원형·평면 CBF의 비교.
- Inserting에서 외부 회피만 적용한 경우와 정렬 제약까지 적용한 경우.

### 9.3 우선순위가 높은 절제 실험

1. 안전 margin: validation에서 정한 작은 값/중간 값/큰 값.
2. $\gamma$: 접근 허용 속도와 정체의 관계.
3. 제어 주기·행동 묶음 길이: 샘플 간 위반 여부.
4. 기하 위치·크기 오차: nominal/과대 추정/과소 추정.
5. 단일 장애물 제약과 다중 장애물 제약.

전체 조합을 처음부터 전수 실행하지 않는다. 주 설정 확정 후 한 요인씩 변경하여 원인을 해석한다.

## 10. 평가 지표와 로그

### 10.1 주 지표

| 지표 | 정의 |
|---|---|
| Task Success Rate | 제한 시간 안에 원래 작업 성공 조건을 만족한 비율 |
| Forbidden-contact-free Rate | 에피소드 전체에서 지정한 금지 접촉이 없는 비율 |
| Safe Success Rate | 작업 성공과 금지 접촉 없음이 동시에 성립하는 비율 |
| 최소 실제 거리 | 내부 시뮬레이션 step에서 측정한 지정 geometry 쌍의 최소 거리 |
| 안전 제약 위반 | 음의 $h$, QP 잔차, 지속 시간·최대 위반량 |
| 개입률 | $\|u_{safe}-u_{nom}\|$이 정한 허용 오차를 넘는 step 비율 |
| 행동 수정량 | 물리 단위별 차이 및 $W$로 정규화한 차이 |
| 정체율 | 사전 정의한 진행도·시간 기준으로 정체한 에피소드 비율 |
| 불가능·실패율 | solver infeasible, 수치 실패, 초기 비안전 상태를 구분 |
| 지연 | 필터 계산 시간과 전체 제어 지연을 별도 측정 |

주 평가는 **Safe Success Rate**로 한다. 접촉이 필요한 작업이므로 모든 접촉을 충돌 실패로 집계하지 않는다. 필터가 보호하는 geometry 쌍의 안전과 전체 환경의 부수적 충돌도 별도로 집계한다.

### 10.2 행동 다양성

D3IL의 작업별 mode 정의를 확인하고 성공한 행동의 모드 분포와 엔트로피를 보고한다. 성공 에피소드에 조건부인 다양성 수치와 성공률을 함께 제시한다. 안전 필터가 기존 모드를 제거했는지, 동일 모드 안에서 경로만 수정했는지 분석한다.

### 10.3 필수 step 로그

```text
policy_seed, context_id, rollout_seed, obstacle_config_id
time, measured_state, command_state, task_phase
raw_action, physical_nominal_action, safe_action
h_per_constraint, actual_distance_per_pair
qp_status, qp_residual, intervention_norm, filter_latency
allowed_contacts, forbidden_contacts, task_progress
```

에피소드 종료 시 success, safe_success, 실패 원인, 실행 시간, 최소 거리, 정체 여부를 저장한다. 명목 행동과 실행 행동의 화살표, 보호 형상, 장애물, $h(t)$를 영상에 함께 표시하면 원인 해석이 쉽다.

## 11. 실험 규모와 통계

### 11.1 제안 규모

- 디버깅: 소수 context와 단일 정책 seed.
- 예비 실험: 작업별 10개 context × 5개 rollout seed, 정책 seed 1개.
- 본 실험: 작업별 30개 test context × 10개 rollout seed × 학습 seed 3개 = 방법·배치 조건당 900개 에피소드.

위 수는 계산 예산에 따른 제안이다. 실제 공개 context 수에 맞추고, 적은 context를 중복 생성하여 독립 표본처럼 취급하지 않는다. 예비 실험으로 계산 시간과 효과 크기를 확인한 뒤 본 실험 규모를 확정한다.

### 11.2 비교 원칙

- 방법 간 동일 context, 장애물 배치, 초기 상태, 가능한 경우 동일 생성 잡음 seed를 사용한다.
- 정책이 분기한 이후에는 같은 seed라도 동일 궤적 조건이 아님을 인지한다.
- 학습 seed별 결과를 보고하고 평균·변동을 제시한다.
- context 내 반복 rollout의 상관을 고려하여 context 단위 paired 차이 또는 계층적 bootstrap 신뢰구간을 사용한다.
- Safe Success Rate의 방법 간 차이를 주 효과로 보고한다.
- 작업 성공률의 비열등성 허용 폭을 주장하려면 validation 결과와 연구 목적을 바탕으로 test 전에 정한다.

## 12. 실행 단계와 완료 기준

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 환경·행동 인터페이스 확인 | 실제 단위·주기·추종 관계·접촉 목록 문서화 |
| 2 | 기본 정책 학습 | 장애물 없는 조건에서 재현 가능한 기본 성능 확보 |
| 3 | QP 단위 검증 | 해석해 대조·잔차·입력 한계·불가능 상태 처리 확인 |
| 4 | Pushing 외부 회피 | 실제 최소 거리와 필요한 접촉 유지 확인 |
| 5 | Inserting 외부 회피 | 삽입 경로를 막지 않고 필터 동작 확인 |
| 6 | 본 비교 실험 | 동일 조건 B0/B1/B2 평가와 신뢰구간 작성 |
| 7 | 강건성·절제 분석 | margin·주기·기하 오차의 주요 영향 확인 |
| 8 | 선택 확장 | 타원체 재현 또는 삽입 정렬 제약 검증 |

고정된 주차보다 완료 기준을 우선한다. 정책 단독이 원래 작업을 거의 수행하지 못하면 안전 필터 효과와 정책 실패가 섞이므로, 먼저 기본 성능을 확보한다.

| 다양성 감소 | 좁은 통로·한 경로로 투영 | 모드별 성공·개입량 분석 |

## 14. 결과 해석과 연구 기여

### 14.1 최소 결과로 뒷받침할 수 있는 주장

> 고정된 flow matching 기반 시각 행동 정책에 CBF-QP를 추가하여, 지정한 접촉 관계와 정확한 기하 정보가 주어진 D3IL 조작 환경에서 금지 접촉 및 작업 성공의 변화를 평가했다.

충돌 감소와 함께 Safe Success Rate가 개선되고 정지 비교군보다 목표 진행이 좋다면, 최소 수정 필터의 실용적 효과를 뒷받침한다. 반대로 성공률이나 다양성이 감소하면 이를 안전 개입의 비용으로 정량화한다.

### 14.2 더 강한 기여를 위한 방향

- 접촉 작업의 단계에 맞춘 안전 집합과 전환 조건.
- 위치 명령·추종 오차·이산 제어를 고려한 실행 안전성.
- 밀리는 물체를 포함하는 다중 물체 안전 모델.
- 정책의 행동 모드를 보존하는 개입 설계.

단순히 VLA에서 언어를 제거하거나 다른 벤치마크에 CBF-QP를 붙이는 것만으로 새로운 알고리즘 기여가 성립한다고 단정하지 않는다. 재현·전이 검증과 새로운 방법 제안을 분리해 보고한다.

## 15. 권장 첫 구현 범위

1. Pushing 작업 하나와 평면 원형 장애물 하나를 선택한다.
2. 정책은 고정하고 안전 필터는 정확한 푸셔·장애물 위치를 사용한다.
3. 푸셔–블록은 허용하고 푸셔–장애물만 금지한다.
4. 정책 행동 인터페이스를 확인한 뒤 속도 또는 위치 증분에 맞는 필터를 구현한다.
5. 단일 제약 해석해와 QP 출력을 대조한다.
6. 정책 단독 / 정지 필터 / CBF-QP를 동일 초기 상태에서 비교한다.
7. 실제 거리·작업 성공·정체·수정량을 확인한 다음 inserting으로 확장한다.

이 순서는 인지 오류, 복잡한 접촉 모델, 타원체 기하를 동시에 구현하지 않고 최종 행동 최적화의 효과부터 분리해 검증하기 위한 것이다.
